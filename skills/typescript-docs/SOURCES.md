## Excluded and why

- Handbook v1: superseded by handbook v2.
- Release notes before 5.0: changes older than the 5.x line are already in force and covered by the current pages.
- Tutorials for ASP.NET Core, Gulp, Angular and React, and Compiler Options in MSBuild: framework or build-tool walkthroughs with no TypeScript rule beyond the pages read.
- The introductions TS for OOPers, TS for Functional Programmers and TS for the New Programmer: beginner orientation, no rule not covered elsewhere.
- The modules reference diagrams: images with no text to extract.

## Conflicts resolved in favor of the 6.0 release notes

Several pages still describe 5.x behavior. The skill states the 6.0 behavior and names the older text where it matters.

- Default `target`: the Basics page says ES5. In 6.0 it is the newest supported version and `es5` is deprecated.
- Default `strict`: the Basics page describes a lenient default. In 6.0 `strict` is `true`.
- Default `types`: the `typeRoots` and Type Declarations pages say every visible `@types` package is included. In 6.0 `types` is `[]`.
- Default `rootDir`: the option page gives the longest common input path. In 6.0 it is the tsconfig directory.
- `esModuleInterop`: the option page describes the off state as default. In 6.0 it cannot be `false`.
- Default `moduleResolution`: the modules pages say `classic` for most `module` values. In 6.0 `classic` is removed and `node10` deprecated.
- `bundler` resolution: the 5.x pages require `module` `esnext` or `preserve`. In 6.0 `commonjs` is also accepted.
- `outFile`, `module` `amd`, `umd`, `system`: the namespaces and modules pages still describe them. 6.0 removes `outFile` and deprecates those `module` values.
- `noUncheckedSideEffectImports` and `libReplacement`: the 5.6 and 5.8 notes give the older defaults. 6.0 turns the first on and the second off.
- `tsc -b` and `noEmitOnError`: the project references page says build mode forces it. The 5.6 notes say build mode continues after errors unless `--stopOnBuildErrors` is set.
- `tsc file.ts` with a tsconfig present: the tsconfig.json page says the config is ignored. In 6.0 it is error TS5112.
- `lib` `dom.iterable`: the `lib` page lists it as a separate entry. In 6.0 `dom` includes it.
- `require()` of ESM: the interop page cites Node.js 22.12.0, the theory page footnote 20.19.0. The skill quotes both.
- Recursive conditional types: only the deprecated Advanced Types page forbids them. The skill does not state the restriction as current.
