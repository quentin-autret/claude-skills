## Registration and locale resolution

- The locale is resolved once per request and kept in `AsyncLocalStorage`, so singleton services, exceptions and pipes translate without the request. https://docs.nestjs.com/application/i18n
  ```typescript
  I18nModule.forRoot({
    defaultLocale: 'en',
    supportedLocales: ['en', 'pl', 'de'],
    fallbacks: { 'de-AT': 'de' },
    loader: new JsonI18nLoader({ path: join(import.meta.dirname, 'i18n') }),
    resolvers: [new QueryLocaleResolver('lang'), new HeaderLocaleResolver('x-lang'), new AcceptLanguageLocaleResolver()],
  })
  ```
  https://docs.nestjs.com/application/i18n#add-catalogs-and-register-the-module
- Catalog JSON is not copied to `dist`: add `"assets": ["i18n/**/*.json"], "watchAssets": true` to `nest-cli.json`. A missing `dist/i18n` fails bootstrap. https://docs.nestjs.com/application/i18n#production-checklist
- The module is global and mounts a middleware that resolves the locale before guards. Resolvers run in order, the first supported candidate wins. Regions match their base language unless listed in `fallbacks`. https://docs.nestjs.com/application/i18n#add-catalogs-and-register-the-module
- `supportedLocales` defaults to the loader's directories: pin it. Default resolver is `AcceptLanguageLocaleResolver` only. https://docs.nestjs.com/application/i18n#reference
- The middleware sets `Content-Language` and `Vary`. Check that caches honor `Vary`. https://docs.nestjs.com/application/i18n#production-checklist
- In `forRootAsync()`, the factory returns loader, resolver and formatter instances. Classes, `imports` and `isGlobal` stay at the top level. https://docs.nestjs.com/application/i18n#options-from-configuration

## Translating

- `this.i18nService.t('orders.confirmed', { args: { id, items } })` reads the request locale. Pass `locale` for background work (emails, jobs). https://docs.nestjs.com/application/i18n#translate-order-confirmations
- Only a numeric arg named `count` selects plural forms. Placeholders cannot nest: translate the plural phrase first. https://docs.nestjs.com/application/i18n#translate-order-confirmations
- Translate when throwing: `throw new NotFoundException(this.i18nService.t('orders.notFound', { args: { id } }))`. Built-in pipes produce English: give them an `exceptionFactory` using the `t()` function. https://docs.nestjs.com/application/i18n#localize-exceptions
- Outside a request, `I18nService` uses the default locale and the `t()` function returns the key. Run background work in `I18nContext.run(locale, fn)`. https://docs.nestjs.com/application/i18n#production-checklist
- Typed keys: augment `I18nTypes` with the English catalog types. https://docs.nestjs.com/application/i18n#add-catalogs-and-register-the-module
- `formatNumber()` and `formatDate()` use the locale, but the currency and time zone must come from data (without `timeZone` the server zone shifts dates). `Intl` separates amount and currency with a no-break space (U+00A0). https://docs.nestjs.com/application/i18n#try-it
- Arguments are inserted unescaped: escape them for HTML emails. https://docs.nestjs.com/application/i18n#production-checklist

## Validation messages

- `I18nValidationPipe` replaces `ValidationPipe` (same options). Constraints without a message are looked up as `validation.<constraint>`. https://docs.nestjs.com/application/i18n#localize-validation-messages
- With Standard Schema, use `I18nStandardSchemaValidationPipe` instead of (not with) `I18nValidationPipe`, and `i18nIssueMessage('orders.tooManyItems')` in schemas. https://docs.nestjs.com/application/i18n#with-zod

## GraphQL, microservices, WebSockets

- The middleware does not wrap subscriptions, and with `setGlobalPrefix()` set `useGlobalPrefix: true` on `GraphQLModule`. Field resolvers are covered only with `fieldResolverEnhancers: ['interceptors']`. https://docs.nestjs.com/application/i18n#localize-graphql-fields
- Microservices and gateways resolve the locale in a global interceptor, after guards: guard errors use the default locale. With `WsAdapter`, set `client.request = request` in `handleConnection()`. https://docs.nestjs.com/application/i18n#microservices-and-websocket-gateways
- A resolver reading the signed-in user sets `readonly afterGuards = true`. https://docs.nestjs.com/application/i18n#use-the-customers-saved-language

## Missing keys, reload, testing, production

- `missingKey: env === 'production' ? 'fallback' : 'throw'`. `'throw'` raises `I18nMissingKeyError` (a 500) and never falls back to the default locale. Vitest sets `NODE_ENV=test`, so tests run under it. https://docs.nestjs.com/application/i18n#handle-missing-keys-and-reload-catalogs
- Fallback is per key, so a composed message can mix languages. https://docs.nestjs.com/application/i18n#handle-missing-keys-and-reload-catalogs
- `JsonI18nLoader({ watch: true })` for development only. https://docs.nestjs.com/application/i18n#handle-missing-keys-and-reload-catalogs
- Tests: `moduleRef.get(I18nContext).run('pl', () => service.method())`, `overrideProvider(I18nLoader).useValue(new InMemoryI18nLoader(catalogs))`. Add a CI test that every locale has the same keys, placeholders and plural forms. https://docs.nestjs.com/application/i18n#testing
- ICU syntax needs a custom `I18nMessageFormatter` (for example `intl-messageformat`). https://docs.nestjs.com/application/i18n#use-icu-message-syntax
