## Naming and scaffold

- Crate `tauri-plugin-{name}`; npm package preferably scoped, `@scope-name/plugin-{name}`. https://v2.tauri.app/develop/plugins/
- Plugin and permission identifiers: lowercase ASCII, digits and hyphens (not leading or trailing), no underscores or uppercase. `sqlite_store` and `SqliteStore` fail the build. https://v2.tauri.app/develop/plugins/
- Scaffold with `npx @tauri-apps/cli plugin new [name]` (`--no-api`, `--android`, `--ios`). It creates `src/{commands,desktop,error,lib,mobile,models}.rs`, `permissions/`, `android/`, `ios/` and `guest-js/`. https://v2.tauri.app/develop/plugins/
- Declare platform support in the crate `Cargo.toml`: https://v2.tauri.app/develop/plugins/

```toml
[package.metadata.platforms.support]
windows = { level = "full" }
android = { level = "partial", notes = "Access is restricted to the Application folder by default" }
ios = { level = "none" }
```

https://v2.tauri.app/develop/plugins/

## Plugin config and lifecycle hooks

- Users configure the plugin in `tauri.conf.json > plugins > <name>`. Read it through the builder's config type; use `Builder::<R, Option<Config>>` to make it optional. https://v2.tauri.app/develop/plugins/

```rust
#[derive(Deserialize)]
pub struct Config { timeout: usize }

pub fn init<R: Runtime>() -> TauriPlugin<R, Config> {
  Builder::<R, Config>::new("<plugin-name>")
    .setup(|app, api| { let timeout = api.config().timeout; Ok(()) })
    .build()
}
```

https://v2.tauri.app/develop/plugins/

- Hooks: `setup` (register mobile plugins, manage state, spawn tasks), `on_navigation` (return `false` to cancel), `on_webview_ready` (per new window), `on_event` (`RunEvent::ExitRequested` with `api.prevent_exit()`, `Exit` for cleanup), `on_drop`. https://v2.tauri.app/develop/plugins/
- Expose a Rust API as a struct named after the plugin, managed as state and reached through an extension trait (pattern: `app.global_shortcut()` via `GlobalShortcutExt`). Shared desktop/mobile logic goes in `lib.rs`. https://v2.tauri.app/develop/plugins/ https://v2.tauri.app/develop/plugins/develop-mobile/

## Commands and their permissions

- Plugin commands are normal Tauri commands, registered with `.invoke_handler(tauri::generate_handler![commands::upload])` on the plugin builder. JS calls them as `plugin:<name>|<command>`, with camelCase argument keys. https://v2.tauri.app/develop/plugins/ https://v2.tauri.app/learn/security/writing-plugin-permissions/

```js
await invoke('plugin:<plugin-name>|upload', { url, onProgress });
```

https://v2.tauri.app/develop/plugins/

- Plugin commands are denied until a permission allows them. List them in `build.rs` to autogenerate `allow-<cmd>` and `deny-<cmd>` under `permissions/autogenerated`: https://v2.tauri.app/develop/plugins/ https://v2.tauri.app/learn/security/writing-plugin-permissions/

```rust
const COMMANDS: &[&str] = &["upload"];
fn main() { tauri_plugin::Builder::new(COMMANDS).build(); }
```

https://v2.tauri.app/develop/plugins/

- `permissions/default.toml` defines the `default` set. Include what the plugin cannot work without (the http plugin is useless without `request`). https://v2.tauri.app/develop/plugins/

```toml
[default]
permissions = ["allow-ping", "allow-write-custom-file"]
```

https://v2.tauri.app/learn/security/writing-plugin-permissions/

- The guest-js wrapper is convenience only: anyone can invoke the command by name, so security lives in permissions and in the command. https://v2.tauri.app/learn/security/writing-plugin-permissions/

## Scopes in plugin commands

- Read the command scope with `tauri::ipc::CommandScope<'_, T>` and the global scope with `tauri::ipc::GlobalScope<'_, T>` (`allows()`, `denies()`). The docs recommend checking both. A permission without commands is a global scope permission. https://v2.tauri.app/develop/plugins/
- For a scope JSON schema, put `schemars = "0.8"` in both `[dependencies]` and `[build-dependencies]` (the scope module is shared with `build.rs`) and call `.global_scope_schema(schemars::schema_for!(scope::Entry))` on `tauri_plugin::Builder`. https://v2.tauri.app/develop/plugins/

## Android and iOS code

- Android: a Kotlin class extending `app.tauri.plugin.Plugin` with `@TauriPlugin`; methods with `@Command` take `invoke: Invoke`. iOS: a Swift class extending `Plugin`, methods `@objc` taking `(_ invoke: Invoke)`, shipped as a Swift package. https://v2.tauri.app/develop/plugins/develop-mobile/
- Android commands run on the main thread: long work causes ANRs. Use `CoroutineScope(Dispatchers.IO).launch { ...; invoke.resolve(...) }`. https://v2.tauri.app/develop/plugins/develop-mobile/
- Arguments: Android `@InvokeArg` classes (`lateinit var` required, `Type? = null` optional, `= value` default) parsed with `invoke.parseArgs(...)`. iOS `Decodable` classes, but iOS has no default values: make the field optional and default it in the command. https://v2.tauri.app/develop/plugins/develop-mobile/
- Plugin config on mobile: Android `getConfig(Config::class.java)`, iOS `parseConfig(Config.self)`. https://v2.tauri.app/develop/plugins/develop-mobile/
- Call native code from Rust with `PluginHandle::run_mobile_plugin("openCamera", payload)`; payload structs use `#[serde(rename_all = "camelCase")]`. https://v2.tauri.app/develop/plugins/develop-mobile/
- Native code calling Rust: JNI on Android (`Java_<package>_<class>_<method>`, `#[no_mangle] pub extern "system"`), C FFI on iOS (`@_silgen_name`, `#[no_mangle] pub unsafe extern "C"`, free returned strings with a dedicated function). It works while the webview is suspended. https://v2.tauri.app/develop/plugins/develop-mobile/
- Android 16 KB pages: NDK 28+ is compliant; otherwise add to `.cargo/config.toml`: https://v2.tauri.app/develop/plugins/develop-mobile/

```toml
[target.aarch64-linux-android]
rustflags = ["-C", "link-arg=-Wl,-z,max-page-size=16384"]
```

https://v2.tauri.app/develop/plugins/develop-mobile/

- Mobile-only hooks: `load`, and on Android `onNewIntent` (notification tap, deep link). https://v2.tauri.app/develop/plugins/develop-mobile/

## Mobile permissions and events

- Android runtime permissions: `@TauriPlugin(permissions = [Permission(strings = [Manifest.permission.POST_NOTIFICATIONS], alias = "postNotification")])`. iOS: override `checkPermissions` and `requestPermissions`. Tauri adds `plugin:<name>|checkPermissions` and `requestPermissions` commands, with states such as `prompt`, `prompt-with-rationale`, `granted`. https://v2.tauri.app/develop/plugins/develop-mobile/
- Emit with `trigger("name", data)` natively; listen in JS with `addPluginListener('<plugin-name>', 'event-name', handler)`. The app must grant the plugin permission (usually `<plugin-name>:default`) or listening is blocked. https://v2.tauri.app/develop/plugins/develop-mobile/

## Old patterns

- Plugin config lives in the top-level `plugins` key of `tauri.conf.json`. The page's example still shows a leftover `"tauri": { ... }` key beside it; do not nest plugin config there. https://v2.tauri.app/develop/plugins/
- The scaffold's JS binding folder is `guest-js`. The page's command example still mentions `webview-src/index.ts`, a stale path. https://v2.tauri.app/develop/plugins/
