## `metadata` or `generateMetadata`

- Default: the static `metadata` export. Use `generateMetadata` only when values depend on route params, external data or parent metadata.
  https://nextjs.org/docs/app/getting-started/metadata-and-og-images#generated-metadata
- Both work only in Server Components. Keep `page.tsx` server-side and move client logic into a child.
  https://nextjs.org/docs/app/api-reference/functions/generate-metadata#why-generatemetadata-is-server-component-only
- Never export both `metadata` and `generateMetadata` from one segment. Same for `viewport` and `generateViewport`.
  https://nextjs.org/docs/app/api-reference/functions/generate-metadata
  https://nextjs.org/docs/app/api-reference/functions/generate-viewport
- Share a database read between `generateMetadata` and the page with React `cache`. `fetch` is memoized automatically.
  https://nextjs.org/docs/app/getting-started/metadata-and-og-images#memoizing-data-requests
- `searchParams` is only available in pages. `redirect()` and `notFound()` work inside `generateMetadata`.
  https://nextjs.org/docs/app/api-reference/functions/generate-metadata#returns
- Extend parent images: `const previousImages = (await parent).openGraph?.images || []`.
  https://nextjs.org/docs/app/api-reference/functions/generate-metadata

## Merging and titles

- Merging is shallow: a child that sets `openGraph`, `robots` or `twitter` replaces the whole parent object. Share common fields through an exported constant and spread it.
  https://nextjs.org/docs/app/api-reference/functions/generate-metadata#merging
- A child that does not set `openGraph` inherits the parent's whole object.
  https://nextjs.org/docs/app/api-reference/functions/generate-metadata#inheriting-fields
- `title: { template: '%s | Acme', default: 'Acme' }` in the root layout. The template applies to child segments only, never to the segment that defines it. `title.absolute` bypasses it.
  https://nextjs.org/docs/app/api-reference/functions/generate-metadata#template
- Evaluation order: root layout, nested layouts, then page.
  https://nextjs.org/docs/app/api-reference/functions/generate-metadata#ordering

## `metadataBase` and URLs

- Set `metadataBase` once in the root layout:
  ```ts
  export const metadata = { metadataBase: new URL('https://acme.com'), alternates: { canonical: '/' } }
  ```
  https://nextjs.org/docs/app/api-reference/functions/generate-metadata#metadatabase
- A relative URL in a URL field without `metadataBase` is a build error. Absolute URLs ignore it.
  https://nextjs.org/docs/app/api-reference/functions/generate-metadata#metadatabase
- With `use cache` in `generateMetadata`, return values must be serializable: return `url.toString()`, not a `URL`.
  https://nextjs.org/docs/app/api-reference/functions/generate-metadata#metadatabase

## File-based metadata

- File-based metadata (`icon`, `apple-icon`, `opengraph-image`, `twitter-image`) has higher priority than `metadata` and `generateMetadata`. Next.js serves the file (hashed in production) and writes the tags.
  https://nextjs.org/docs/app/api-reference/file-conventions/metadata
- A deeper `opengraph-image` wins over ones above it in the folder structure.
  https://nextjs.org/docs/app/getting-started/metadata-and-og-images#static-open-graph-images
- `favicon.ico` only at the top of `app/` and never generated by code (use `icon`). `apple-icon` refuses `.ico` and `.svg`.
  https://nextjs.org/docs/app/api-reference/file-conventions/metadata/app-icons
- `opengraph-image` files over 8 MB and `twitter-image` files over 5 MB fail the build. Add `opengraph-image.alt.txt` for alt text.
  https://nextjs.org/docs/app/api-reference/file-conventions/metadata/opengraph-image#image-files-jpg-png-gif
- These special handlers are cached by default unless they use Request-time APIs.
  https://nextjs.org/docs/app/api-reference/file-conventions/metadata

## Open Graph images and `ImageResponse`

- Generate in `opengraph-image.tsx` with `ImageResponse` from `next/og`. Export `alt`, `size` and `contentType`, spread `...size` into the options.
  https://nextjs.org/docs/app/api-reference/file-conventions/metadata/opengraph-image#generate-images-using-code-js-ts-tsx
- `params` and `id` of image functions are Promises. `generateImageMetadata` itself still gets plain `params`.
  https://nextjs.org/docs/app/api-reference/functions/generate-image-metadata#version-history
- Limits: flexbox and a CSS subset (no `display: grid`), 500 KB bundle including fonts, fonts in `ttf`, `otf` or `woff` only.
  https://nextjs.org/docs/app/api-reference/functions/image-response#behavior
- Read fonts once at module scope: `await readFile(join(process.cwd(), 'assets/Inter-SemiBold.ttf'))`.
  https://nextjs.org/docs/app/api-reference/functions/image-response#custom-fonts

## Sitemaps and robots

- `sitemap.ts`, `robots.ts` and `manifest.ts` return `MetadataRoute.Sitemap`, `.Robots` and `.Manifest`.
  https://nextjs.org/docs/app/api-reference/file-conventions/metadata/sitemap
- Split with `generateSitemaps()` returning `[{ id: 0 }, ...]`, 50,000 URLs each. Since v16.0.0 the `id` passed to `sitemap()` is a `Promise<string>`.
  https://nextjs.org/docs/app/api-reference/functions/generate-sitemaps
- `alternates.languages` emits `hreflang` links. Point robots at the sitemap with `sitemap: 'https://acme.com/sitemap.xml'`.
  https://nextjs.org/docs/app/api-reference/file-conventions/metadata/sitemap#generate-a-localized-sitemap
  https://nextjs.org/docs/app/api-reference/file-conventions/metadata/robots

## Viewport

- `viewport`, `themeColor` and `colorScheme` live in `export const viewport` or `generateViewport`, not in `metadata`.
  https://nextjs.org/docs/app/api-reference/functions/generate-viewport
- `charset` and `width=device-width, initial-scale=1` are added by default.  https://nextjs.org/docs/app/getting-started/metadata-and-og-images#default-fields

## Streaming metadata and bots

- On dynamic pages metadata streams into `<body>` after the UI. HTML-limited bots (default list: some Google crawlers such as AdsBot-Google, Bingbot, Twitterbot, Slackbot) get it in `<head>`. Googlebot runs JavaScript and reads the streamed tags.
  https://nextjs.org/docs/app/api-reference/functions/generate-metadata#streaming-metadata
  https://nextjs.org/docs/app/api-reference/config/next-config-js/htmlLimitedBots#default-list
- `htmlLimitedBots` replaces the default list, it does not extend it.
  https://nextjs.org/docs/app/api-reference/config/next-config-js/htmlLimitedBots

## Cache Components

- `generateMetadata` reading `cookies()`, `headers()`, params or uncached data on an otherwise prerenderable page errors. Without runtime data, add `'use cache'` to it. With runtime data, render a `<Suspense><Connection /></Suspense>` marker (`Connection` awaits `connection()`). Never `await connection()` directly in the page.
  https://nextjs.org/docs/app/api-reference/functions/generate-metadata#with-cache-components
- The viewport cannot stream. With external data but no runtime data, use `'use cache'`. With runtime data, wrap the document in `<Suspense>` in the layout (the page's sample wraps `<html>`).
  https://nextjs.org/docs/app/api-reference/functions/generate-viewport#with-cache-components

## JSON-LD and unsupported tags

- Render a `<script type="application/ld+json">` tag in `layout.js` or `page.js`, and replace `<` with its unicode equivalent to prevent XSS:
  ```tsx
  <script type="application/ld+json" dangerouslySetInnerHTML={{ __html: JSON.stringify(jsonLd).replace(/</g, '\\u003c') }} />
  ```
  https://nextjs.org/docs/app/guides/json-ld
- The Metadata API has no `http-equiv`, `<base>`, `<noscript>`, `<style>` or `<script>`. Render them in the layout, or send HTTP headers.
  https://nextjs.org/docs/app/api-reference/functions/generate-metadata#unsupported-metadata
- Resource hints: `ReactDOM.preload` or `preconnect` from a Client Component.
  https://nextjs.org/docs/app/api-reference/functions/generate-metadata#resource-hints
