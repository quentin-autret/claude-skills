## Component hierarchy

- Order per segment: layout > template > error > loading > not-found > page. `error.js` does not catch errors of the same segment's layout or template. `loading.js` does not wrap the same segment's layout.
  https://nextjs.org/docs/app/api-reference/file-conventions/error
- Root layout errors need `app/global-error.js`, which renders its own `<html>` and `<body>`, gets no global styles and cannot export `metadata`.
  https://nextjs.org/docs/app/api-reference/file-conventions/error#global-error

## Layouts and pages

- `params` and `searchParams` are Promises. `searchParams` is a plain object, and `?a=1&a=2` gives an array.
  ```tsx
  export default async function Page(props: PageProps<'/blog/[slug]'>) {
    const { slug } = await props.params
  }
  ```
  https://nextjs.org/docs/app/api-reference/file-conventions/page#searchparams-optional
- `PageProps`, `LayoutProps` and `RouteContext` are global helpers generated by `next dev`, `next build` or `next typegen`. No import needed. `LayoutProps` also types named slots.
  https://nextjs.org/docs/app/api-reference/file-conventions/layout#layout-props-helper
- Layouts do not re-render on navigation, so they never receive `searchParams` or the pathname. Read them in a Client Component child.
  https://nextjs.org/docs/app/api-reference/file-conventions/layout#query-params
- Layouts cannot pass data to children. Fetch again in the child and dedupe with React `cache` (fetch dedupes itself).
  https://nextjs.org/docs/app/api-reference/file-conventions/layout#fetching-data
- `loading.js` sits below the layout, so it gives no fallback for `cookies()`, `headers()` or uncached fetches read in the layout. Navigation blocks, and with Cache Components the build errors. Wrap that read in its own `<Suspense>` or move it to `page.js`.
  ```tsx
  <Suspense fallback={<NavSkeleton />}><DashboardNav /></Suspense>
  ```
  https://nextjs.org/docs/app/api-reference/file-conventions/layout#interaction-with-loadingjs
- Do not hand-write `<title>` or `<meta>` in layouts. Use the Metadata API.
  https://nextjs.org/docs/app/api-reference/file-conventions/layout#root-layout
- Navigating between different root layouts (route groups) is a full page load.
  https://nextjs.org/docs/app/api-reference/file-conventions/route-groups#caveats
- `template.js` remounts on navigation: state resets, effects rerun. Its key includes dynamic params, not search params.
  https://nextjs.org/docs/app/api-reference/file-conventions/template#behavior

## `loading`, status codes and `not-found`

- Streaming starts with status 200. `notFound()`, `forbidden()` and `unauthorized()` keep 404, 403 or 401 only when called before anything suspends. After that the status stays 200. For a streamed 404, Next.js injects `<meta name="robots" content="noindex">`.
  https://nextjs.org/docs/app/api-reference/file-conventions/loading#status-codes
- For a guaranteed status code, check in Proxy before streaming.
  https://nextjs.org/docs/app/api-reference/file-conventions/loading#status-codes
- The root `app/not-found.js` also handles every unmatched URL. Its default UI follows the OS color scheme, not your theme.
  https://nextjs.org/docs/app/api-reference/file-conventions/not-found
- `global-not-found.js` is experimental (`experimental.globalNotFound`). It bypasses layouts, so it imports its own CSS and fonts. Use it with several root layouts.
  https://nextjs.org/docs/app/api-reference/file-conventions/not-found#global-not-foundjs-experimental
- The `forbidden` and `unauthorized` APIs are experimental and need `experimental.authInterrupts: true`.
  https://nextjs.org/docs/app/api-reference/config/next-config-js/authInterrupts

## Parallel and intercepting routes

- Every `@slot`, and `children`, needs a `default.js`, otherwise the build fails. Return `null` or call `notFound()` in it.
  https://nextjs.org/docs/app/guides/upgrading/version-16#parallel-routes-defaultjs-requirement
- In conditional slots (`role === 'admin' ? admin : user`) both slots render on the server and run their fetches. Authorize inside each slot.
  https://nextjs.org/docs/app/api-reference/file-conventions/parallel-routes#conditional-routes
- If one slot at a level is dynamic, all slots at that level are dynamic.
  https://nextjs.org/docs/app/api-reference/file-conventions/parallel-routes#slots
- Modal pattern: `@auth/default.js` returns `null`, `@auth/(.)login/page.js` intercepts, close with `router.back()`. To close via `<Link>`, add `@auth/[...catchAll]/page.js` returning `null`.
  https://nextjs.org/docs/app/api-reference/file-conventions/parallel-routes#modals
- `(.)`, `(..)` and `(...)` follow route segments, not folders, so `@slot` folders do not count. Interception happens only on soft navigation.
  https://nextjs.org/docs/app/api-reference/file-conventions/intercepting-routes#convention

## Route Handlers

- No `route.ts` in the same segment as `page.tsx`.
  https://nextjs.org/docs/app/getting-started/route-handlers#route-resolution
- Context `params` is a Promise: `ctx: RouteContext<'/users/[id]'>`, then `await ctx.params`.
  https://nextjs.org/docs/app/api-reference/file-conventions/route#route-context-helper
- With Cache Components, `GET` handlers prerender like pages unless they touch the network, a database, request data or random values.
  https://nextjs.org/docs/app/getting-started/route-handlers#with-cache-components
- Webhooks need no `bodyParser` config: read `await request.text()`.
  https://nextjs.org/docs/app/api-reference/file-conventions/route#webhooks
- `headers()` is read-only, so return a new `Response` to set headers.
  https://nextjs.org/docs/app/api-reference/file-conventions/route#headers
- Use metadata files for sitemap, robots, icons and Open Graph images instead of handlers.
  https://nextjs.org/docs/app/api-reference/file-conventions/route#non-ui-responses

## `generateStaticParams` and dynamic segments

- Return an array of objects, one key per segment. Catch-all values are arrays: `{ slug: ['a', '1'] }`.
  https://nextjs.org/docs/app/api-reference/functions/generate-static-params
- It runs at `next build` and is not called again during ISR revalidation.
  https://nextjs.org/docs/app/api-reference/functions/generate-static-params
- A layout can generate params for its own segment and above, never below.
  https://nextjs.org/docs/app/api-reference/functions/generate-static-params#multiple-dynamic-segments-in-a-route
- With Cache Components it must return at least 1 param (an empty array is a build error).
  https://nextjs.org/docs/app/api-reference/functions/generate-static-params
- With Cache Components, runtime params not in the samples are validated at first request, as are branches the samples do not hit.
  https://nextjs.org/docs/app/api-reference/file-conventions/dynamic-routes#with-cache-components
- Without Cache Components, `dynamicParams = false` turns unlisted params into a 404.
  https://nextjs.org/docs/app/api-reference/file-conventions/route-segment-config/dynamicParams
- Params are `string | string[] | undefined`. Validate at runtime and call `notFound()`.
  https://nextjs.org/docs/app/api-reference/file-conventions/dynamic-routes#typescript

## Root params and i18n

```tsx
// app/[lang]/layout.tsx
import { lang } from 'next/root-params'
export async function generateStaticParams() { return [{ lang: 'en' }, { lang: 'fr' }] }
export default async function RootLayout(props: LayoutProps<'/[lang]'>) {
  return <html lang={await lang()}><body>{props.children}</body></html>
}
```
https://nextjs.org/docs/app/api-reference/functions/next-root-params

- Root params are the dynamic segments above the root layout. Names must be valid identifiers (no `[post-slug]`). Server Components only.
  https://nextjs.org/docs/app/api-reference/functions/next-root-params
- Inside `use cache`, a root param getter adds only the params it reads to the key.
  https://nextjs.org/docs/app/api-reference/functions/next-root-params#behavior-with-caching-directives
- Detect the locale from `Accept-Language` in Proxy and redirect. Validate `lang` with a type guard and `notFound()`. Keep dictionaries in `server-only` modules.
  https://nextjs.org/docs/app/guides/internationalization

## Segment config: `runtime`, `maxDuration`, `preferredRegion`

- Remove `runtime = 'edge'` (deprecated) and `preferredRegion` (deprecated). Node.js is the default.
  https://nextjs.org/docs/app/api-reference/file-conventions/route-segment-config/runtime
- `maxDuration` (seconds) set on a page also bounds every Server Action used on it.
  https://nextjs.org/docs/app/api-reference/file-conventions/route-segment-config/maxDuration
- `src/app` is ignored when `app/` exists at the root. Keep `public/`, config files and `.env*` at the root.
  https://nextjs.org/docs/app/api-reference/file-conventions/src-folder
